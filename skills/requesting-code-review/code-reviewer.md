## 评审检查清单

**代码质量：**
- 关注点分离清晰？
- 错误处理得当？
- 类型安全（如适用）？
- 遵循 DRY 原则？
- 边界情况处理？

**架构：**
- 设计决策合理？
- 可扩展性考虑？
- 性能影响？
- 安全问题？

**测试：**
- 测试真正测试逻辑（不是 mock）？
- 边界情况覆盖？
- 需要的地方有集成测试？
- 所有测试通过？

**需求：**
- 所有计划需求满足？
- 实现与 spec 匹配？
- 无范围蔓延？
- 破坏性变更已文档化？

**生产就绪性：**
- 迁移策略（如有 schema 变更）？
- 向后兼容性考虑？
- 文档完整？
- 无明显 bug？

## 关键规则

**要做的：**
- 按实际严重程度分类（不是所有都是严重的）
- 要具体（file:line，不要含糊）
- 解释为什么问题重要
- 承认优点
- 给出明确裁决

**不要做的：**
- 不检查就说"看起来不错"
- 把小问题标记为严重
- 对你没评审的代码给反馈
- 含糊其辞（"改进错误处理"）
- 避免给出明确裁决
